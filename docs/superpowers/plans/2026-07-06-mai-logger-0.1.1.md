# mai-logger 0.1.1 Release + Re-vendor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release `maithemewp/mai-logger` 0.1.1 with a one-line fix so PHPUnit (CLI, no WordPress) can run in any plugin that bundles the logger, then re-vendor it into mai-analytics so the test suite runs reproducibly on a clean clone / in CI.

**Architecture:** mai-logger is a standalone Composer package pulled into each mai plugin via a `files` autoload entry (`init.php`), which runs on every request. That entry currently hard-exits when `ABSPATH` is undefined — which kills PHPUnit before it bootstraps. The fix adds a `'cli' === PHP_SAPI` escape. This is a dependency change in a separate repo plus a vendor bump here.

**Tech Stack:** PHP, Composer, PHPUnit 9.6, git.

## Global Constraints

- **This is dev/test-only.** Production is unaffected — `ABSPATH` is always defined in a running WordPress, so 0.1.0 already no-ops the exit correctly. Do NOT treat this as a production bugfix.
- **mai-logger source lives at `~/LocalPackages/mai-logger`** (git repo). It is **tag-based**: `composer.json` has no `version` field and mai-analytics requires it via a VCS repo pointed at `https://github.com/maithemewp/mai-logger` with `^0.1`. Composer resolves it from the GitHub URL's **tags**, so **a `v0.1.1` tag must be committed and pushed to GitHub** before the re-vendor (Task 2) can pull it. Only `v0.1.0` is tagged today.
- **Current partial state (as of 7/6/26):** `~/LocalPackages/mai-logger/init.php` ALREADY has the CLI tweak and `register( '0.1.1', ... )`, but it is an **uncommitted** working-tree edit. `Mai_Logger.php` still has `const VERSION = '0.1.0'` and the old `defined( 'ABSPATH' ) || exit;` guard. So Task 1 = finish the version bump, commit, push, and tag — not write from scratch.
- The exact code change is one line in `init.php` (line ~15): `defined( 'ABSPATH' ) || exit;` → `defined( 'ABSPATH' ) || 'cli' === PHP_SAPI || exit;`.
- Version strings to bump (three spots): `init.php` `Mai_Logger_Bootstrap::register( '0.1.0', ... )` → `'0.1.1'`; `Mai_Logger.php` `@version 0.1.0` → `0.1.1`; `Mai_Logger.php` `const VERSION = '0.1.0'` → `'0.1.1'`.
- The bootstrap protocol comment in `init.php` says `register()`'s signature is FROZEN — do not change the signature, only the version string argument.
- mai-analytics ships via PUC on `main`; its committed `vendor/` is production-only (no dev deps). See [[reference_mai_analytics_release]].

**Interfaces:**

Run the suite to confirm it still boots: `WP_TESTS_DIR=/tmp/wordpress-tests-lib vendor/bin/phpunit --filter Test_Stats`
Expected: `OK (12 tests...)`.

- [ ] **Step 3: Regenerate PRODUCTION vendor metadata, then commit on develop**

The dev deps are installed locally, so `installed.json`, `installed.php`, and the autoloaders all reference phpunit. Regenerate them production-only before committing. **`composer dump-autoload --no-dev` is NOT sufficient** — it strips dev entries from `autoload_*.php` but leaves `installed.json` and `installed.php` polluted (verified 7/6/26: 89 phpunit refs remained in `installed.json`, 14 in `installed.php`). Use `composer install --no-dev`, which physically removes the dev packages and rewrites all metadata production-only:
```bash
composer install --no-dev   # rewrites installed.json/installed.php + autoloaders with 0 dev refs
git add composer.lock vendor/maithemewp/mai-logger vendor/composer/installed.json vendor/composer/installed.php
git commit -m "build: re-vendor mai-logger 0.1.1 (CLI-safe autoload for PHPUnit)"
composer install   # restore dev deps locally for testing
```
The `.gitignore` allowlist already keeps dev-dep *code* out of the commit; `composer install --no-dev` keeps dev-dep *metadata* out too. After `install --no-dev` the whole `vendor/composer/` tree is production-only, so staging the two `installed.*` files is enough for a files-autoload package like mai-logger (the `autoload_*.php` maps don't change); do NOT stage `data/bot-patterns.php` (separate chore).

- [ ] **Step 4: Changelog rides 1.3.0 (decision 1A).** Do NOT add a mai-analytics version/changelog for this alone — 1.2.0 is already shipped and we don't re-cut it.
